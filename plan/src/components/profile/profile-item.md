# ProfileItem

## 组件职责与使用场景

ProfileItem 展示一个普通 Profile 的紧凑列表行，并承载激活、刷新、拖拽、批量选择、编辑和文件操作入口。

## Props 与数据输入

- 输入 Profile UID、Profile 数据、当前选中与激活状态。
- 接收刷新数据、激活、编辑、保存、删除和批量选择回调。
- 不接收或向后端传递任意文件路径。

## 视觉状态

- 名称为主要信息；第二行以等宽样式显示实际加载文件名，来源或描述跟随其后。主 Profile 使用 CONF 覆盖时显示低饱和 `CONF Override` 标签；桌面宽度下右侧显示用量、到期和更新时间。
- 当前 Profile 只使用中性背景，不改变名称或图标的颜色与字重。
- loading/activating 分别使用旋转刷新图标和行内进度遮罩。
- 拖拽时沿用既有位移与层级反馈；批量模式显示复选框。

## 交互状态

- 点击行激活，拖拽手柄只负责排序，刷新按钮只更新当前远程 Profile。
- 可见更多按钮和右键打开同一菜单；按钮点击必须阻止触发行激活。
- local/remote 主 Profile 的菜单在“编辑文件”后提供 CONF 转换：首次转换直接执行，已有 CONF Override 时显示“从 YAML 重新生成 CONF”并要求确认覆盖风险。
- 转换期间复用行级 loading 状态并禁止重复操作；成功后刷新列表。当前 Profile 同时强制重新增强并应用 CONF，非当前 Profile 等待下次激活时生效。
- Open File 与 Reveal in Finder 是两个独立菜单项；后者只传 UID 给后端解析。
- hover 使用中性表面，交互按钮保留 MUI 的 hover、focus-visible、disabled 状态。

## 键盘与边界状态

- 批量复选框和行尾按钮可通过键盘聚焦；拖拽沿用 KeyboardSensor。
- 长名称和来源单行省略，并用原生 title 保留完整内容。
- 实际文件名在窄窗口仍保留并单行省略，title 同时提供逻辑名称和完整文件名。
- 重新生成确认文案必须明确：转换源始终是声明 YAML，现有 CONF 的手工修改和注释会被覆盖。
- 小于约 680px 时隐藏右侧次要元数据，但保留名称、刷新和更多按钮。
- 本地 Profile 不显示刷新按钮，更新时间为只读文字；远程 Profile 的更新时间可切换到下次计划更新时间。

## 组合关系

- 使用 `ProfileBox` 提供统一列表表面。
- 编辑器、规则/代理/分组编辑、二维码和确认弹窗继续使用既有独立组件。
