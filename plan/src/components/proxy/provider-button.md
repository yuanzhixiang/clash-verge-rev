# 代理集合入口与弹窗

## 组件职责

组件负责在存在代理 Provider 时展示管理入口，并提供订阅信息浏览、单项更新和全部更新能力。

## 使用场景与数据

- 由 Policy 页面页头使用，从代理数据上下文读取 `proxyProviders`。
- 没有 Provider 时不渲染入口，不为页面保留空占位。
- 更新完成后同步刷新代理节点和 Provider 数据；单项失败通过现有通知系统反馈，全部更新时单项失败不阻断后续任务。

## 视觉结构

- 入口为 36px 高的低饱和 tonal 按钮，与 Policy 页面同组的 Test All 操作保持完全一致的高度；出站模式和 Chain Proxy 属于页面模式工具区，继续使用 38px 高度。
- 弹窗宽度约 680px，使用实色主面板、18px 圆角、hairline 边框和环境阴影。
- 标题栏只展示标题、更新全部和关闭按钮，不设置底部操作栏。
- Provider 使用单一 hairline 列表容器，相邻行以横向细分隔线区分；不得使用独立白色卡片、彩色描边标签或行尾竖向分隔栏。
- 列表容器高度由实际 Provider 行决定，不设置会在少量数据时产生空白的固定最小高度。
- 行结构与 Rule Provider 保持一致：名称位于首行，节点数量和载体类型位于其下方，更新时间靠右；无订阅信息时行高约 64px、行尾操作区宽 44px。
- 名称使用 14px/600 字重，节点数量和载体类型使用低对比中性标签，更新时间为 12px 次要信息。
- 存在订阅信息时展示已用/总量、到期时间和 Pill 圆角进度轨道；缺少总量时隐藏进度条而非展示错误进度。

## 交互状态

- hover 仅轻微抬升行表面，不能大面积染成强调色。
- 单项更新按钮位于行尾，hover 时才增强图标颜色；更新中禁用并旋转。
- 全部更新期间按钮显示 loading 并禁用，关闭弹窗不取消已提交任务。

## 响应式与可访问性

- 弹窗最大高度不得超过视口，列表内容独立滚动。
- 小于约 520px 时更新时间移到名称与标签下方；更新全部和关闭入口保持可见，行尾刷新按钮保持固定宽度。
- 长名称、更新时间和流量信息不能挤压行尾刷新按钮；文本必要时截断并保留 `title`。
- 更新、更新全部与关闭按钮都必须具有可访问名称和可见键盘焦点状态。
- Dialog 通过 Portal 渲染，Paper 必须重新声明 shell 主题变量，兼容 Light、Dark 与自定义主色。
