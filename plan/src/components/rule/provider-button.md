# 规则集合入口与弹窗

## 组件职责

组件负责在存在规则集合时展示入口，并提供查看、更新单个集合和更新全部集合的弹窗。

## 使用场景

- 规则页顶部工具栏。

## Props 与数据输入

- 组件无外部 props，从规则数据上下文读取 `ruleProviders`，从刷新器上下文读取刷新函数。

## 视觉状态

- 入口使用 38px 高、无常驻描边的紧凑 tonal 按钮，与搜索框等高；图标与文字间距为 8px，水平内边距为 12px。
- 弹窗宽度约 640px，采用与主面板一致的表面、hairline 边框和圆角；标题栏展示标题、更新全部和关闭入口，不展示集合数量，不设置底部操作栏。
- 集合使用单一 hairline 列表容器，相邻行由细分隔线区分；每行约 60–64px，展示名称、规则数量、更新时间、载体类型和行为类型。
- 元数据使用低对比中性填充标签；单项刷新位于行尾，不使用竖向分隔栏。
- Dialog 通过 Portal 渲染时必须在 Paper 上重新声明壳层主题变量，禁止透明表面。

## 交互状态

- 没有集合时不渲染入口。
- 点击集合行主体打开只读规则详情弹窗；行尾刷新按钮只执行更新，不触发详情。
- 更新单项时只禁用对应按钮并显示旋转状态。
- 更新全部时串行处理集合，单项失败不阻断后续集合。
- 成功、失败和无集合反馈沿用现有通知系统。

## 键盘、Hover、Focus、Disabled 与 Loading

- 入口、集合行主体、更新全部、关闭和单项更新按钮均可通过键盘访问；集合行主体支持 Enter 和 Space。
- hover 只提升表面层级；`focus-visible` 使用主题主色焦点环。
- 更新中按钮使用 disabled 状态并保持可理解的加载反馈。

## 边界状态

- 集合名称和更新时间过长时截断，不挤压操作按钮。
- 关闭弹窗不取消已提交的更新任务。
- 同一次管理弹窗会话缓存已读取的详情；单项更新只失效对应缓存，全部更新清空全部详情缓存。
- 列表内容独立滚动，标题栏固定；小于约 520px 时更新时间移到名称下方，刷新按钮保持在右侧。
- Paper 最大高度不得超过视口，light/dark 下背景、边框与阴影均必须有效。

## 组合关系

- 由规则页工具栏使用，并组合 `RuleProviderDetailDialog` 展示具体规则。入口与搜索框之间保持 12px 间距；窄屏时入口保持内容宽度，搜索框换行并占满可用宽度。更新完成后同步刷新规则和规则集合数据。
