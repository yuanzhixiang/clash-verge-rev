# 规则配置操作

## 模块职责

模块统一定义规则类型、校验、序列化、运行时 YAML 读取和 Profile 规则增强文件变更，供规则页与现有 Profile 规则编辑器复用。

## 数据输入与输出

- 输入运行时 YAML，输出精确的 `rules` 字符串数组、代理组、规则集合和子规则名称。
- 输入规则表单值，输出 Mihomo 标准规则字符串。
- 输入单个 URL 或带路径域名，输出基于公共及私有后缀的可注册主域名；不能安全转换时返回 null。
- 输入标准规则字符串，解析为类型、内容、策略和 no-resolve 表单值。
- 输入增强文件与新增、删除、原位替换动作，输出保留其它字段的下一份 YAML。

## 业务规则

- 新增只写 `prepend` 或 `append`，不直接修改原始 Profile。
- 删除本地新增规则时从 `prepend/append` 移除；其它规则加入精确 `delete`。
- 编辑本地规则时在原 `prepend/append` 数组索引替换；编辑原始规则时写入 `replace: [{ from, to }]`。
- 再次编辑 replacement 目标时更新原条目；改回 from 时删除 replacement；删除 replacement 目标时移除 replacement 并将 from 加入 delete。
- 数组缺失或 YAML 为空时按空数组处理，未知顶层字段必须保留。
- 完全相同规则不得重复写入同一数组；delete 已包含目标时保持幂等。
- 新增规则默认定义固定为 `DOMAIN-SUFFIX`，不得依赖 `RULE_DEFINITIONS` 的数组下标。

## 错误与边界

- YAML 非对象、运行时索引越界或规则不是字符串时抛出可展示错误，不写文件。
- 复杂规则和 `no-resolve` 必须使用运行时原始字符串，不能由表格字段反向猜测。
- 标准规则解析以首段为类型、末段为策略、可选末尾 no-resolve，中间段重新用逗号连接；未知类型拒绝可视化编辑。
- 完全相同的重复运行时规则不得创建 replacement，避免一个编辑动作影响多行。
- 域名归一化只服务粘贴交互，不在序列化阶段改写手动输入或历史规则。
- 保存和运行时应用失败的回滚由现有 `saveProfileFile` 保证；后置 Merge/Script 重建目标时由页面二次验证并恢复原内容。
