# 应用布局

## 页面定位

应用布局负责承载全局导航、更新入口、实时流量和路由内容。视觉采用 Surge 式桌面工具布局：冷色侧栏与浮起的主内容面板形成稳定层级，同时继续服从项目主题与用户自定义主色。macOS 使用原生 Overlay 标题栏，让壳层画布实际绘制到标题栏下方，避免 AppKit 标题栏框架灰色与应用蓝灰画布之间出现断层。

## 用户流程

- 用户通过左侧导航切换页面，当前页面以中性底色和清晰图标状态标识。
- 用户可通过导航区域右键菜单折叠侧栏、进入菜单排序模式或恢复默认顺序。
- 用户可在侧栏底部持续查看上传、下载与内存状态。
- 更新入口、页面预加载、通知和窗口控制沿用现有行为。

## 信息架构

- 展开侧栏默认宽度约为 220px，包含品牌区、导航区和流量区。
- 折叠侧栏宽度为 72px，只显示品牌图标与导航图标，并隐藏流量区。
- 主内容区与窗口边缘保留 12px 间距，以 16px 圆角面板承载各路由页面。
- macOS 保留原生居中标题与红黄绿窗口按钮；布局顶部预留 28px 壳层安全区并作为拖拽区域，正文、品牌和导航从安全区下方开始。
- Windows 保留原生标题栏；Linux 已有自绘标题栏和缩放句柄保持兼容。

## 主要交互

- 导航支持点击、键盘聚焦、hover 预加载和拖拽排序。
- 展开态显示图标与标签；折叠态通过 `title` 和 `aria-label` 提供名称。
- 小于约 720px 时仅通过 CSS 自动呈现紧凑侧栏，不写回用户的折叠配置。
- 页面切换、日志页特殊挂载和错误边界逻辑不改变。
- macOS 装饰开启时显示顶部安全拖拽区；用户关闭系统装饰后隐藏该安全区，继续使用已有自绘标题栏。

## 加载、空态与错误态

- 主题未准备完成时继续显示与当前壳层画布色一致的空白启动表面，避免闪白或标题栏断色。
- 路由页面自行负责加载、空态和错误态；布局层继续由全局错误边界兜底。
- 菜单配置缺失项时跳过该项，不阻塞其它导航渲染。

## 权限与平台状态

- 布局不引入用户权限判断；主窗口只获得同步原生窗口背景色所需的最小 Tauri 权限。
- macOS、Windows 使用系统装饰；Linux 保留现有无边框窗口控制逻辑。
- 用户主题、背景图、菜单图标模式和侧栏折叠设置继续生效。
- macOS 的 Light、Dark 和跟随系统主题切换必须同步更新原生窗口背景；同步失败只记录错误，不阻塞应用主题切换。

## 响应式行为

- 宽屏和默认窗口使用 220px 侧栏与 12px 主面板间距。
- 用户折叠或窗口宽度不超过约 720px 时使用 72px 紧凑导航。
- 小窗口下主内容面板间距缩小为 8px、圆角缩小为 12px，内容不得被侧栏覆盖。

## 文案口径

- 导航标签沿用现有本地化文案。
- 菜单排序、折叠和恢复默认顺序沿用现有文案，不增加 Surge 品牌相关描述。

## 可访问性

- 导航按钮必须具有可见的 `focus-visible` 状态。
- 折叠态必须保留可访问名称和原生提示。
- 选中态不能只依赖颜色，应同时使用背景层级和字重区分。

## 关键 UI/UX 约束

- 侧栏使用冷色半透明表面，主面板使用更高层级的实色表面和轻量阴影。
- 强调色仅用于焦点、状态和少量操作，不大面积染色。
- 不改变路由、菜单顺序持久化、实时流量订阅和窗口装饰行为。
- 壳层颜色变量由统一主题函数生成；使用 MUI Portal 的弹窗必须在自己的 Paper 上应用同一组变量，不能依赖 Layout DOM 继承。
- macOS 标题栏使用 Tauri `Overlay` 样式，使 WebView 壳层画布成为标题栏的真实背景；28px 安全拖拽区必须隔离正文与交通灯，不移动原生窗口按钮。
- 改动保持在现有布局入口和样式文件内，不引入新的布局框架。
