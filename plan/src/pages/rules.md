# 规则页面

## 页面定位

规则页面用于按 Mihomo 实际匹配优先级浏览和维护当前生效规则，并快速按规则类型、匹配值或策略筛选。页面采用 Surge 式紧凑桌面表格，命中次数直接使用 Mihomo 核心统计，规则增删和启停写入当前 Profile 的规则增强文件。

## 用户流程

- 用户进入页面后查看规则标题和规则表格。
- 用户可搜索 Type、Value、Policy，并继续使用大小写、整词和正则匹配选项。
- 存在规则集合时，用户可打开规则集合弹窗并更新单个或全部集合，也可点击集合行查看 YAML、Text 或 inline 集合中的具体规则并搜索；MRS 集合明确显示暂不支持预览。
- 用户可通过表格底部的加号新增顶部或底部规则。
- 用户可单选一行并通过减号删除；删除订阅原始规则时写入精确删除覆盖，不直接改订阅文件。
- 用户可双击规则行打开编辑弹窗，在不改变优先级槽位的前提下修改类型、匹配值、策略和 no-resolve。
- 用户可通过行尾开关把规则置为「保留但禁用」：规则仍留在列表原位并保留 ID，只是不再参与匹配；再次打开即恢复。
- 用户可在表格区域滚动浏览大量规则。

## 信息架构

- 页头左侧仅展示规则标题，不显示额外说明文案。
- 页头右侧为规则集合入口和搜索框。
- 表格固定展示 `ID / Type / Value / Policy / Used / Enabled` 六列，默认不展示列间竖线和逐行横线。
- ID 使用接口返回的 `index`；Used 使用 Mihomo `extra.hitCount`，字段缺失时显示 `—`。
- Enabled 列为行尾开关，状态以 Mihomo `extra.disabled` 为准，不由前端本地推断。
- 表格底部为固定操作栏，左侧提供 `＋ / －`，不提供 Reset Counter。
- `＋ / －` 按钮默认背景透明，仅在 hover 时显示操作背景高亮。

## 主要交互

- 搜索匹配 Type、Value、Policy 任一字段，结果保持原始规则顺序。
- 表头固定，列表继续使用虚拟滚动；表头和数据行统一为 32px。
- 行使用低对比斑马纹与表面色差组织信息，通过 hover、focus 和单选反馈强化当前目标。
- 行尾开关切换「保留但禁用」；开关的点击与双击不冒泡为选择或编辑，切换不改变当前选中行。
- 被禁用的行压暗信息列并对 Value 加删除线，开关本身保持满对比度以便重新启用；规则不移动、不隐藏、ID 不变。
- 点击行或在聚焦行按 Enter/Space 选择删除目标；搜索改变、目标消失和删除完成时清除选择。
- 双击行或在聚焦行按 F2 打开编辑；单击、Enter、Space 的选择语义保持不变。
- 新增弹窗支持 Type、Value、Policy、no-resolve 和顶部/底部位置，默认插入顶部。
- 编辑弹窗预填完整运行时规则，允许修改全部规则字段但不显示位置控件。
- 删除前确认，并通过运行时 YAML 的 `rules[index]` 获取完整规则文本。
- 长文本以省略号收束，并通过原生标题提示完整内容；单元格文本允许复制。
- 页面可见时每 2 秒刷新规则以更新 Used，页面隐藏或离开后停止轮询。

## 筛选、排序与分页口径

- 页面只有客户端搜索筛选，不提供排序和分页。
- 筛选结果严格保留 Mihomo 返回顺序，因为该顺序决定规则优先级。
- 正则表达式无效时沿用搜索组件的错误提示，不执行异常匹配。
- Used 更新不得改变排序或当前选中行。

## 加载、空态与错误态

- 数据刷新沿用现有查询和重试机制，刷新期间保留当前可用数据。
- 没有规则或筛选无结果时使用现有 `BaseEmpty`。
- 规则集合更新成功或失败继续使用现有通知反馈。
- 增删操作期间锁定对应按钮；保存失败由现有保存链路回滚文件并提示错误。
- 编辑保存后必须验证同一运行时索引已变为新规则且相邻顺序未改变；验证失败恢复原增强文件。
- 删除覆盖应用后若规则仍由后置 Merge/Script 生成，则恢复原增强文件并提示用户编辑规则来源。
- 启停保存后必须回查核心规则表：同一 ID 仍是同一条规则且 `extra.disabled` 已变为目标值，否则恢复原增强文件并提示未生效。
- 切换期间只锁定该行开关，不锁定整表；写入失败时依赖 2 秒轮询把开关回弹到核心真实状态。

## 权限态

- 页面不引入新的系统权限状态。
- 没有规则集合数据时隐藏规则集合入口。
- 没有活动 Profile、缺少规则增强文件或无法映射原始规则时禁用增删编辑和启停开关并说明原因。
- 完全相同的运行时重复规则无法安全定位时不允许编辑，也不允许启停：禁用标记按规则原文寻址，重复原文无法区分目标行。

## 响应式行为

- 宽屏下标题与工具栏同排，搜索框保持约 320–380px 的稳定宽度。
- 窄屏下标题和工具栏改为纵向排列，搜索框占满可用宽度。
- 六列表格保留合理最小宽度；空间不足时表格区域横向滚动，不静默隐藏列。Enabled 列宽度固定，不参与弹性分配。
- 底部操作栏保留在表格结构内，不随虚拟列表纵向滚动。

## 文案口径

- 标题、列名和搜索占位符均使用规则命名空间的本地化键。
- Used 表示当前规则集加载以来的核心命中次数，不描述为流量或连接数。
- 启停文案必须点明「保留在列表中」，不能让用户误解为删除；不出现 Reset Counter 文案。

## 可访问性

- 虚拟化表格提供 `table / row / columnheader / cell` 语义。
- 搜索框和规则集合入口保留明确的可访问名称与焦点状态。
- 可选行提供 `aria-selected`，加号、减号和对话框字段具有本地化可访问名称。
- 行使用 F2 提供与双击等价的键盘编辑入口。
- 颜色不能作为 Policy 信息的唯一载体，文本内容始终可见。

## 关键 UI/UX 约束

- 表格使用普通 hairline 完整外框与小圆角界定列表区域，但不使用列间竖线或逐行横线；内部以留白、低对比斑马纹和交互表面层级组织信息，并仅在表头与列表、列表与底部操作栏之间保留分隔线。
- 搜索框常驻普通 hairline 边框，输入及占位文字使用 13.5px 紧凑字号；规则集合入口与搜索框同为 38px 高，两者保持 12px 间距。入口默认使用轻量表面，仅在 hover、按下或 focus 时增强反馈；窄屏下入口保持内容宽度，搜索框换行占满可用宽度。
- 表头、数据行和横向滚动容器必须保持列宽对齐。
- 横向滚动容器不得为内层纵向滚动条额外预留空白 gutter。
- 增删编辑必须使用当前 Profile 的 `prepend / append / delete / replace` 增强能力，不修改 Mihomo API 或原始订阅。
- replace 只替换原始规则所在槽位；订阅更新导致其数字 ID 变化不视为移动。
- 启停使用规则增强文件的 `disabled` 段，存规则原文而不是下标：下标会随任意增删整体位移，原文在订阅更新后仍可对齐。
- 被禁用的规则照常进入 runtime 配置和核心规则表，禁用状态由后端在配置 apply 之后调用核心接口重放，见 `plan/src-tauri/src/core/rule_disable.md`；前端不直接调用该接口。
- 不自行统计或持久化 Used，不实现 Reset Counter。
